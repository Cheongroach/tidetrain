# 公开文件与原始运行证据怎样对应

公开仓库保留可以解释实验的代码、结果和过程，但不放模型权重、训练 token 数据体、Adam 大张量或凭据。内部地址、部署身份和操作者路径被换成匿名标签。

## 三种哈希不是同一回事

| 哈希 | 标识什么 | 能否用公开副本重算 |
| --- | --- | --- |
| 运行时 config_hash／source_sha256 | 当时实际配置与代码 | 配置路径已匿名化，公开副本通常不能重现原 hash |
| blob SHA256 | 实际 checkpoint、delta、恢复对象的内容 | 需要取得原始对象；Git 中通常只有引用和字节数 |
| PUBLIC_EXPORT_MANIFEST.json | 公开副本文件内容 | 可以对当前公开文件重新计算 |

因此公开文件哈希变化不意味着原训练对象变了；保存同一个原始对象引用也不意味着所有文档来自同一时刻。

## 易读版如何追溯

每份 `xxx-friendly` 都链接对应原文，原 Markdown 和 Notebook 按原字节保留。易读版按问题和证据重排，省略的操作流水仍在原文，不把补充说明假装成原始日志。

`DOCUMENTS-friendly.json` 列出原文与易读版路径、原始 SHA256、保留理由及编辑覆盖范围。Notebook 的易读副本保留代码单元格，重写说明并清空执行输出；没有因为整理文档而运行训练。

## 对话记录的适用范围

原对话导出覆盖当时可读取的会话。易读版保留技术决策、用户修正和证据入口，不复制冗长工具流水、审批评估片段或系统注入文本；因此它是有来源的主题阅读稿，不是完整逐字记录。

千卡入口选错和用户暂停属于后续明确修正，易读版会写明，避免旧“排队中”被读成现状。历史原文保留，是为了让读者能核对当时表述。

实测依据仍是完整验证、接受记录、独立恢复和状态审计。图表与友好措辞都不能把 CPU 测试变成 GPU 成果。[阅读地图](READING_GUIDE-friendly.md)列出全部原文对应入口。
