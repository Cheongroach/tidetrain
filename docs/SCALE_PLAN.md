# 百卡与千卡执行计划

当前状态（2026-10-25）：基线已发布；分片归约、持久账本、紧凑恢复 manifest 和千卡启动入口已实现。104／1000 H20 请求实际执行后在平台启动阶段失败；修正后的 1000 A10 请求已提交，经历 staging 和平台自动续试、目前 queued，尚未产生该规模训练结果。详见 [扩容执行记录](../results/scale-20261025/REPORT.md)。

用户明确要求直接上千卡，**P2／P3 不再作为 P4 资源申请的前置门槛**。回归与真实 checkpoint 数学审计和千卡请求同时推进。

## 目标与判断标准

目标是提高可抢占、低带宽资源上的有效训练吞吐和恢复能力。核心指标为接受 token/s、每百万接受 token 的 GPU·h、恢复时间、重算 token、中央和区域传输字节、CPU/RAM 峰值，以及固定训练 token 下的完整验证 loss。

当前 Qwen2.5-0.5B smoke 的验证 loss 上升 0.2842；不能把增加 GPU 数量或改变通信语义当成已解决质量问题。容量、协议和质量结果分别报告。

## 已确认的瓶颈

参数量为 494,032,768，FP32 参数大小 \(D=4P=1,976,131,072\) bytes。每个 warm round 下发参数 \(D\) 与恢复状态约 \(2D\)，回收 delta \(D\) 与恢复状态约 \(2D\)，共约 \(6D=11.86\) GB/island。100／1000 个单卡 island 对应 1.186／11.857 TB；这是字节契约推导，不是实测流量。

现有控制器会加载整个全局状态及 delta，HDFS CLI 每次独立启动进程；已有 C3 会话 319 次命令累计 2,143.189 秒。当前唯一控制器只由本地锁保护，不能防止跨主机双主。

## 架构与语义

全局控制器仅发布成员、分片计划和全局版本。区域 CPU 网关缓存全局分片，保存该区域 optimizer/RNG/游标，执行有界归约；GPU island 仅与 HTTP 网关及自己的本地盘交互。保持每轮区域状态持久化，避免以降低 checkpoint 频率换取表面流量收益。

第一版保持同步 local-SGD 的数学语义，分片结果已与基线核验一致。当前实现仍是一个 CPU HTTP 网关；SQLite 仅支持该宿主机上的崩溃恢复和唯一接受权，不能视为多主机共识。网关归约持有少量 chunk，GPU worker 仍会完整恢复模型／optimizer 到 CPU；没有证明 worker RAM 随 chunk 大小有界，也没有减少 checkpoint 总字节。

随后把 Streaming/Decoupled DiLoCo 的碎片同步、延迟合并、quorum 窗口作为单独算法配置。必须记录 fragment 版本和每次应用事件；异步恢复需要事件重放，不能声称等价于原同步结果。

同机 4–8 GPU 的 DDP/FSDP island 只在真实网络与运行时验证通过后启用。异构 island 按接受 token 加权，同一逻辑 worker 的多个部署副本不能重复计数。

## 数据与资源

WikiText-2 训练流仅有 2,517,232 token。千个单卡 island 每轮 65,536,000 token 会重复消费该流；大规模容量测试需明确输入用途，大规模质量测试需扩大固定版本语料。资源查询仅反映当前账号和控制面视角，不能承诺排队 ETA。

任何阶段的资源申请、预检通过或容器启动都属于设置证据。只有收齐实际参与列表、终态、产物、全量验证和成本数据后，才能给出该规模的实测结论。
