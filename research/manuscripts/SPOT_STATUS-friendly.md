# 第一轮 Spot 预约：资源窗口结束前没有训练

这份记录回答的是一次有限预约窗口发生了什么。2026-10-24 的两个逻辑槽位各申请一张 A10，到当日 17:00，北京时间结束；控制端始终没有拿到可用的双端点，训练没有启动。

## 准备工作与训练结果要分开

离线包和镜像准备完成，不等于 GPU 训练完成。独立镜像 v2 构建成功，并在一侧保存了新配置；另一侧浏览器更新提交超时，回读仍是旧镜像。曾有 HTTP health 或平台 TASK_RUNNING，但没有收齐两端 HTTP/HDFS 预检、CUDA 训练产物或全局提交。

控制端终态为 `order_expired_before_both_endpoints`，没有 `completed.json`。这一窗口的训练量应记为 0，而不是把镜像成功作为训练成功。

## 资源在窗口结束后怎样处理

守护在 16:57 提交删除两个目标 deployment。随后官方 GET 为 not found，服务部署列表为空，证明部署记录被移除；没有底层 GPU 计费流水，不能报告精确账单。

两个 deployment 从创建到删除的驻留累计约 4.82 实例小时。滚动更新曾报告新旧副本重叠，所以驻留目标数和实际 GPU·h 还需要交付、实例起止记录核对。

## 从这个窗口学到了什么

官方 deployment tasks 加认证 HTTP 更适合核验具体实例：检查镜像、新 replicaset、配置身份和 UUID。仅依赖 SDK 没发现端点，不能说明平台完全没交付。这个发现路径的四项 CPU 测试通过，真实 GPU 双端验收在该窗口没有完成。

浏览器日志请求还返回 HTTP400／Relay URL 为空，没有取得完整启动异常栈。基础镜像入口是兼容性疑点，不是已确认失败根因。
