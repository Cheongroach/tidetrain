# 诊断镜像交接：构建成功不代表训练完成

本文件记录早期 ICM 诊断镜像从 1.0.0.2 升到 1.0.0.3 的下发。它在当时尚未完成 GPU round；后续使用更新镜像并完成两卡实验。最终结论应以终验记录为准。

## 当时为何升级镜像

诊断版增加失败子进程日志认证回传、CUDA runtime 记录和全量验证 job，同时更新嵌入文件 SHA256。初始权重、数据和训练超参数保持一致，使运行环境变化不被误读为算法变化。

两端镜像保存／下发后，官方 deployment GET 回读了新版本和 replicaset。回读证明配置已下发，不证明 CUDA 或模型更新成功。

## 寿命配置中的两个数

目标 worker 寿命为 10,740 秒，外层启动命令 timeout 为 10,770 秒。原手稿同时保留过一端旧 3,540／3,570 秒配置，应按实际回读分辨，不能任选一组数当成当前状态。

服务进程时限、训练 run deadline 和预约到期是不同约束。恢复过期实验应建立新的 run、只继承已提交状态，不能编辑 immutable run.json 延长父窗口。

## 下发后的证据链

镜像配置回读 → 新实例身份／配置哈希 → CUDA BF16 运算 → 真实训练子进程 → 收齐 delta、Adam、RNG、cursor → 全局 commit → 同条件完整验证。

其中任何一步都不能被前一步替代。两个服务即使各保留八个副本，原训练器实际只选两个单 GPU 槽位，不是 16 卡 DDP。

原交接含具体 ICM 绑定字段与历史预约；部分公开地址已匿名化，不能直接点击恢复内部操作。后来的 GPU 终验以[实验报告](../../results/qwen05b-4round/REPORT-friendly.md)为准，历史操作详情在[原文](ICM_V3_HANDOFF.md)。
